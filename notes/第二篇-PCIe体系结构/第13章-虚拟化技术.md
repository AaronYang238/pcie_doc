# 第13章　PCIe 总线与虚拟化技术

> **导读**：虚拟化要求「把一个物理设备安全地分给多台虚拟机」。这需要三件套：**IOMMU**（DMA 地址翻译与隔离）、**ATS**（设备侧缓存翻译结果）、**SR-IOV**（一个物理设备虚拟出多个功能）。本章是 PCIe 面向云/数据中心的关键一章。
>
> **⭐现代化重点章**：**PASID、ATS/PRI、Scalable IOV、与 CXL 的关系**。
>
> **本页为大纲骨架**，正文按 [CLAUDE.md §5.1](../../CLAUDE.md) 骨架填充。

## 术语表

| 英文 / 缩写 | 中文 | 一句话释义 |
|-------------|------|-----------|
| IOMMU | I/O 内存管理单元 | 翻译并隔离设备 DMA 地址（VT-d / AMD-Vi） |
| IOVA | I/O 虚拟地址 | 设备发出的、需经 IOMMU 翻译的地址 |
| ATS, Address Translation Services | 地址翻译服务 | 设备缓存翻译结果（ATC） |
| ATC | 地址翻译缓存 | 设备侧缓存的地址翻译表项 |
| PRI, Page Request Interface | 页请求接口 | 设备触发缺页，支持可分页 DMA |
| PASID | 进程地址空间 ID | 让一个设备同时服务多个进程/VM 的地址空间 |
| SR-IOV | 单根 I/O 虚拟化 | 一个 PF 虚拟出多个 VF |
| PF / VF | 物理/虚拟功能 | 管理用主功能 / 可直通给 VM 的轻量功能 |

## 13.1 IOMMU
- **13.1.1 IOMMU 的工作原理**：⭐把设备发出的 **IOVA** 翻译成物理地址，并做访问隔离；页表 + IOTLB。
- **13.1.2 IA 处理器的 VT-d**：Intel 实现 —— DMAR、Root/Context Table、二级页表、中断重映射（呼应 [第10章](第10章-MSI和MSI-X中断.md)）。
- **13.1.3 AMD 处理器的 IOMMU**：AMD-Vi 的等价机制。

## 13.2 ATS（Address Translation Services）
- **13.2.1 TLP 的 AT 字段**：TLP 头中的 Address Type，标识地址是「未翻译/已翻译/翻译请求」。
- **13.2.2 地址转换请求**：设备向 IOMMU 请求翻译，把结果缓存在设备侧 **ATC（Address Translation Cache）**。
- **13.2.3 Invalidate ATC**：页表变更时使设备侧缓存失效的握手（Invalidation Request/Completion）。

## 13.3 SR-IOV 与 MR-IOV
- **13.3.1 SR-IOV 技术**：⭐**PF（Physical Function）+ 多 VF（Virtual Function）**；每个 VF 有独立 BAR/配置，可直通给虚拟机；配合 ARI 扩展功能号。
- **13.3.2 MR-IOV 技术**：多根（多主机）共享设备（实际部署少，了解即可）。

## 13.4 小结
- 「翻译（IOMMU/ATS）+ 复制（SR-IOV）」如何共同实现安全高效的设备直通。

## 📘 SPEC 7.0 现代化补充清单（本章重头）
- **PASID（Process Address Space ID）**：TLP Prefix 携带 PASID，让单个设备同时服务多个进程/VM 的地址空间 —— **共享虚拟内存（SVM/SVA）** 的基础。
- **PRI（Page Request Interface）**：设备可触发缺页请求，配合 ATS 实现**可分页的设备内存访问**（无需全钉住内存）。
- **Scalable IOV（S-IOV）**：比 SR-IOV 更细粒度、更省资源的虚拟化（ADI + IMS，呼应 [第10章](第10章-MSI和MSI-X中断.md) IMS），面向大规模云与 DPU/GPU。
- **与 CXL 的关系**：CXL 复用 PCIe 物理层，`CXL.cache/CXL.mem` 提供设备-主机内存一致性，是 PCIe 之上的一致性扩展 —— 现代异构互联的方向。
- **AER 与可靠性**：虚拟化环境下的错误隔离（Advanced Error Reporting）值得并列一提。
